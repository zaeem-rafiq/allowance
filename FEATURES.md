# Features

What Allowance does today, in plain words, and the test that proves each feature. This is the product's contract: change a row in the same pull request as the feature, and `./check` fails when a proof is missing. Planned work belongs in the plan, not here.

Proof names a test file and, after `#`, the name of the test inside it. Every proof names its test; a file alone is not a proof. The first proof is the feature's end-to-end test, and every end-to-end test must be named by some row. Several proofs are separated by commas.

|---|---|---|---|---|

Claude Sonnet proposes the mandate line by line; clauses it cannot enforce appear under "Not enforced" and must be accepted or removed before signing. Visitors are capped at $120 a week, and only the owner can change the demo parent's rule, which the public sees read-only. | Open `/rule`, or `/mandate` for the demo rule | `e2e/rule-writer.spec.ts#a parent writes a rule and sees the signed mandate`, `e2e/rule-writer.spec.ts#lists clauses it cannot enforce`, `e2e/rule-writer.spec.ts#the public sees the demo mandate read-only` | The card shows wrong lines, Sign works with an undecided clause, or a visitor changes the demo rule |
